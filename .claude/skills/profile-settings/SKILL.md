# profile-settings

`profile.md` のうち、決まった形式で書く部分（`## 表示機能` の各行）と、雛形（`profile_template.md`）に加わった節の有無を、ユーザーに選択肢で聞きながら書き換える。
雛形の更新を取り込んだ後に実行すると、新しく加わった表示機能や節がここで示される。

パスはすべてリポジトリのルートからの相対パス。

## 0. 実行できるか確認する

- `profile.md` が無い場合は、雛形リポジトリか初期設定前の複製リポジトリである。「README の手順で複製リポジトリを作り、`profile.md` を用意してください」と報告して終了する。
- ユーザーに質問できない実行（日次ルーティンなどの無人実行）では、何も書き換えずに終了する。

## 1. 読み込み

- `profile.md` と `profile_template.md`。HTML コメント（`<!-- -->`）の中は書き方の例なので、節や指定として扱わない。
- **機能の台帳**：`.claude/skills/news-digest/SKILL.md` の手順5「表示機能」の表（機能名 → 仕様ファイル）。表にある機能だけが有効な機能名である。
- 台帳の各仕様ファイル（`.claude/skills/news-digest/features/<x>.md`）から次を読む。
  - 説明：最初の見出しの直後の段落
  - 設定項目：`## 設定` の表（`項目`・`必須`・`意味`）。とりうる値の一覧や既定値は `意味` 列に書かれている
- `profile.md` の `## 表示機能` の行は `- <機能名>: on|off（項目: 値、項目: 値）` の形式（括弧は全角、項目の区切りは `、`）。`on` 以外の値は off とみなす（news-digest 手順5と同じ規則）。

## 2. 現状を示す

次の2つを、1つのメッセージに表で示す。

**表示機能**

| 機能名 | 状態 | 設定 | 説明 |
|---|---|---|---|

- 状態は `on` / `off` / `未記載`。`未記載` は、台帳にあるが `profile.md` に行が無い機能（雛形から新しく加わった機能）。`## 表示機能` 節そのものが無い場合は、すべて `未記載`。
- `profile.md` にあって台帳に無い機能名は、表の下に「不明な機能名（ダイジェストでは無視される）」として挙げる。勝手に消さない。

**雛形にあって profile.md に無い節**

- `profile_template.md` の `##` 節のうち、`profile.md` に同じ見出しが無いものを挙げ、その節が何をするものかを1行で添える（template の説明文や README から要約する）。
- 無ければ「すべての節がそろっています」と書く。

## 3. 節を追加する

雛形にあって `profile.md` に無い節がある場合だけ行う。

- AskUserQuestion（multiSelect）で、追加する節を選んでもらう。選ばれなかった節は追加しない。
- 追加する節は、`profile_template.md` の見出しから次の見出しの直前までを、説明文・HTML コメントの例も含めてそのまま写す。
- 挿入する位置は、template での並び順に合わせる。template でその節の直前にある節のうち `profile.md` にもある最後のものの後ろに置く（無ければ最初の `##` 節の前）。
- `## 表示機能` を追加する場合、機能の行は template のものを写さず、手順4〜6の結果で書く。

## 4. 表示機能の on / off

`## 表示機能` 節が `profile.md` に無く、手順3でも追加しなかった場合は、この手順から手順6までを飛ばす。

- AskUserQuestion（multiSelect）で「on にする表示機能」を聞く。選択肢は台帳の機能で、`description` に今の状態と説明を書く。今 on の機能は `label` の末尾に「（現在 on）」を付ける。
- AskUserQuestion の選択肢は1問に4つまでなので、機能が5つ以上なら4つずつ別の問いに分ける（1回の呼び出しに4問まで）。
- 選ばれた機能は on、選ばれなかった機能は off にする。

## 5. 設定値

on にした機能ごとに、仕様の `## 設定` の項目を聞く。1回の AskUserQuestion に4問まで、1問1項目。

- 前から on で、今回も on のままの機能は、まず「<機能名>の設定を変えますか」を1問で聞く（選択肢は「このまま」「変える」）。「このまま」なら残りは聞かない。
- `意味` 列に値の一覧があり、4つ以下に収まる項目は、その値を選択肢にする。収まらない場合は、既定値・今の値・よく使う値を選び、残りは Other で入力してもらう。既定値の `label` には「（既定）」を付ける。
- 値が自由な項目（地域名、座標など）は、今の値があれば「このまま（<今の値>）」を、必須でなければ「書かない（<既定の決まり方>）」を選択肢にし、新しい値は Other で入力してもらう。必須で今の値も無い場合は、template の行にある値を例として選択肢に出す。
- 仕様の `## 設定` に項目の表が無い機能（月齢など）は、設定を聞かない。on / off だけを書く。
- 答えは `意味` 列に書かれた形式に合っているかを確かめる（例：天気の `緯度経度` は `43.06, 141.35` の形）。合わない場合は、その項目だけもう一度聞く。
- 必須の項目が決まらないまま on にはしない。もう一度聞いても決まらなければ off にし、最後の報告でそのことを伝える。

## 6. 書き込む

`profile.md` の `## 表示機能` 節の、機能の行だけを書き換える。節の説明文、ほかの節、HTML コメントには触れない。

- 1機能1行で `- <機能名>: on|off（項目: 値、項目: 値）`。項目は仕様の `## 設定` の表の順に並べる。値を書かない項目と、既定値と同じ値を選んだ項目は括弧に入れない。括弧の中が空になるなら括弧ごと省く。
- off にした機能も、設定は行に残す（次に on にするときに使う）。
- `未記載` だった機能は、off のままでも行を足す（次回から `未記載` と出ないように）。
- 行の順は今の順を保ち、新しい行は節の末尾に足す。この順がダイジェストでの表示順になる。
- 不明な機能名の行はそのまま残す。

手順3でも手順6でも何も変わらなかった場合は、「変更はありません」と報告して終了する。

## 7. 確認とコミット

- `git diff -- profile.md` の結果を示す。
- AskUserQuestion で「コミットしてプッシュ」と「保存だけ（コミットしない）」のどちらにするかを聞く。
- コミットしてプッシュする場合は次を行う。`origin` の `main` に直接プッシュし、`template` remote にはプッシュしない。

```bash
git add profile.md
git commit -m "profile: 配信設定を更新"
git push origin HEAD:main
```

- プッシュが拒否された場合は、エラー内容をそのまま報告する。force push はしない。

最後に、変えた内容（追加した節、on / off を変えた機能、変えた設定）を箇条書きで報告する。
